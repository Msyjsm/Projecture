# Projecture Preview Testing

Projecture's release and Preview userscripts can remain enabled at the same time. A runtime hash router makes exactly one copy initialize on each ChatGPT page:

- A normal ChatGPT URL runs the release copy.
- A URL ending in `#proj-preview` runs the Preview copy.
- Adding or removing `#proj-preview` reloads the page and switches channels.

The Preview interface identifies itself as **Projecture [PREVIEW]**.

## One-time installation

Install the generated userscript from:

`https://raw.githubusercontent.com/Msyjsm/Projecture/preview/Projecture.preview.user.js`

Leave both Projecture entries enabled in Tampermonkey. You do not need to disable one copy before using the other.

The fixed `preview` branch is generated by GitHub Actions after pushes to development or release branches. Do not edit its generated files directly.

## Getting a newer Preview build

A browser refresh, including Ctrl+F5, only reloads the userscript version Tampermonkey already installed. To retrieve a new build:

1. Open the Tampermonkey dashboard.
2. Choose **Check for userscript updates**, or revisit the fixed install URL above.
3. Reload the ChatGPT tab with `#proj-preview` in its URL.

Preview versions append the GitHub Actions run number to the source version, making the installed build easy to identify.

## Isolation and live-data warning

Release settings use `projecture.*` browser-local keys. Preview settings use `projecture.preview.*` keys, so experimenting with layout, filters, colors, and favicon rules in Preview does not overwrite the release copy's local configuration.

The ChatGPT account itself is not sandboxed. Project creation, deletion, and conversation moves performed through Preview affect the same live account used by the release copy.

## Workflow permissions

If the Preview workflow cannot publish the generated branch, enable **Read and write permissions** under the repository's **Settings → Actions → General → Workflow permissions**.
